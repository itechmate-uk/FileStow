FileStow 1.0.2: a project that gets its first symlinks keeps being backed up.

- **Symlinks.** A project whose remote copy already existed was held back as soon as
  it got symlinks (for example `node_modules/.bin` links created by a build), with
  "migration confirmation required", until the one-time link migration was confirmed
  by hand. Now only a symlink at a path the remote already holds as a real file or
  folder needs that confirmation; new symlinks are simply backed up as links.
- **Failure notices.** That outcome is now explained in the ntfy message (it said
  "No known error pattern matched").
